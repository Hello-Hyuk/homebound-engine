# 계속 동작 모드 계획 (아직 수집은 켜지 않음)

이 문서는 사용자가 계속 동작 방향에 동의한 뒤의 준비안이다.
위치 수집을 시작한다는 명시적 말이 있기 전까지는 수집, 지오펜스,
제안을 켜지 않는다.

## 지금 상태

* 엔진은 라이브러리, JSON CLI, MCP 형태로 호출할 때만 동작한다.
* 엔진용 크론, 백그라운드 프로세스, 서비스는 없다.
* 메시지 스냅샷으로 일회성 판정한 것이 전부이다.

## 계속 동작이 되려면 필요한 것

1. 위치 수집 동의: 귀가 판정 동의와 일상 경로 학습 동의를 분리해서 받는다.
2. 폰 쪽 수집부: Android Fused Location과 지오펜스, iOS CLLocationUpdate와
   CLMonitor를 쓰는 앱 또는 어댑터가 필요하다. 이 VM만으로는 폰 GPS를
   백그라운드에서 계속 가져올 수 없다.
3. 공용 지오펜스: 바깥 3km, 중간 1km, 안쪽 150m에서 200m 트리거.
   최종 판정은 엔진의 150m 거리 계산으로 한다.
4. VM 쪽 처리: 상태 전환이 있을 때만 요약(상태, 등급, 근거)을 받는다.
   원시 궤적은 단말에만 두고 서버로 보내지 않는다.
5. 제안 정책: 오전 9시부터 오후 9시 30분, 같은 귀가 세션 1회,
   하루 1에서 2건 이내, 같은 조건 3회 연속 거절 시 중단.
   자동 제어는 하지 않고 사용자가 고른 항목만 실행한다.

## VM에서 지금 당장 할 수 있는 중간 단계

* 사용자가 메시지를 보낼 때 함께 온 위치 스냅샷으로 엔진을 돌리는 것.
  이것은 연속 수집이 아니고, 스냅샷 판정이다.
* 주기 체크를 크론으로 만드는 것은 사용자가 주기와 목적을 명시적으로
  정한 뒤에만 만든다. 주기를 정하지 않은 채로 만드는 일은 하지 않는다.

## 시작 조건

다음 세 가지가 모두 확인돼야 수집을 켠다.

* 수집 범위와 보관 기간에 대한 명시적 동의
* 폰 쪽 수집부를 어떻게 만들지 결정 (앱 신규 개발 또는 기존 도구 연동)
* 제안만 하고 자동 제어는 하지 않는다는 규칙 유지

## 끄는 방법

제안 메시지마다 출처와 끄는 방법을 밝힌다. 끄면 수집, 지오펜스,
제안이 함께 멈춘다.
